# study

Инструмент командной строки для учёбы в Moodle: сроки и задания, материалы курсов,
отправка ответов с вложениями, релизы на GitVerse и SourceCraft.

- **Дедлайны и задания.** Сроки сдач со статусом ответа, просроченное, изменившиеся
  сроки и новые задания. Учитывает то, чего нет в обычном списке заданий: элементы
  с ограничением доступа, тесты с числом попыток и лимитом времени, выбор темы доклада
  вместе с признаком, выбрана ли она.
- **Материалы курсов.** Показывает появившиеся файлы поимённо и скачивает их
  в `stash/` предмета — методички, слайды, программы.
- **Ответ на задание.** Собирает текст со ссылками на репозитории, релизы и скринкасты,
  загружает PDF отчёта и презентации вложениями и отправляет ответ. Отправка выполняется
  только с флагом `--confirm`: сохранение ответа в Moodle необратимо.
- **Релизы.** Создание релиза по тегу и загрузка файлов на GitVerse и SourceCraft,
  из каталога любого курса.
- **Состояние работ.** Что уже собрано, закоммичено, выпущено и отправлено — по данным
  git, собранных PDF и релизов на хостингах.

Всё это собирается в один отчёт командой `study state` — ближайшие дедлайны, обновления
в курсах, тесты впереди, баллы и рядом готовность каждой работы к сдаче.

Запускать её руками обычно не нужно: **основной режим работы — ежедневная задача
Claude Code Desktop**, которая читает тот же отчёт в JSON, забирает новые материалы
курсов и каждое утро присылает разбор — что горит сегодня, что готово к сдаче
и что осталось сделать. Настройка — в разделе ниже.

## Требования

- Linux или WSL (из Windows — через `wsl.exe`, см. ниже)
- `python3` 3.8 и новее, только стандартная библиотека
- `git`
- токены: Moodle (служба *mobile web service*), GitVerse, SourceCraft — нужны только
  для тех сервисов, которыми пользуетесь

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/nowherewashere/study-digest/master/setup.sh -o setup.sh && chmod +x setup.sh && ./setup.sh; rm -f setup.sh
```

Где взять токены:

| Сервис | Где |
|--------|-----|
| Moodle | профиль → «Ключи безопасности» → служба *Moodle mobile web service*; значение показывается один раз |
| GitVerse | иконка пользователя → Настройки → Управление токенами, доступ «Репозитории» |
| SourceCraft | Home → Access → Personal Access Tokens |

Свои настройки лежат в `config.env` — он создаётся при установке из
`config.env.example` и в репозиторий не попадает. Осталось вписать в него курсы:
готовые строки печатает сама программа, нужные перенести и подставить коды каталогов.

```bash
digest/study courses
digest/study digest      # первый запуск сохраняет снимок состояния
```

## Ежедневная сводка в Claude Code

Основной способ пользоваться инструментом: локальная задача Claude Code Desktop
запускает `study state --json` каждое утро и присылает разбор — что горит сегодня,
что уже готово к сдаче и что осталось сделать. Руками команды нужны редко.

Задача забирает новые материалы курсов в `stash/`, а по несделанным работам смотрит
методичку и коротко описывает, что в ней требуется, и предлагает первое сообщение
для новой сессии, чтобы сразу начать работу.

Как завести: Claude Code Desktop → вкладка Code → **Routines** → New routine →
**Local** (облачной задаче недоступны локальные файлы и токены).

| Поле | Значение |
|------|----------|
| Working folder | корень учебной директории |
| Schedule | Daily, 9:00 |
| Instructions | текст из `daily-digest-prompt.md` |

После создания нажать **Run now** и на запросах разрешений выбрать «always allow»:
разрешение выдаётся один раз на `study`, а не на каждую команду, иначе следующие
запуски остановятся на подтверждении.

### Claude Code в Windows, `study` в WSL

Задача Claude Code Desktop запускается в Windows, а программа живёт в WSL. Рабочая
папка тогда задаётся как `\\wsl.localhost\<дистрибутив>\home\<...>\study`, но оболочка
у задачи остаётся windows-овой (Git Bash), и `cd /home/...` в ней не работает. Все
команды идут через `wsl.exe`:

```bash
MSYS_NO_PATHCONV=1 wsl.exe -d ubuntu -- bash -c '~/work/study/digest/study state --json'
```

- `MSYS_NO_PATHCONV=1` обязателен: без него Git Bash подставляет windows-путь вместо
  unix-пути в аргументах (`/tmp/x.sh` → `C:/Program Files/Git/mnt/c/...`), и команда
  не находится.
- Однострочники `bash -lc '…'` переживают не всякие кавычки: в цикле `for d in …`
  переменная приходит пустой, и проверка молча обходит не те каталоги. Всё длиннее
  одной команды класть в скрипт.
- Скрипт пишется из Windows прямо в файловую систему WSL — `//wsl.localhost/<дистрибутив>/tmp/x.sh`,
  запускается как `bash /tmp/x.sh`.
- Разрешение запрашивается на `wsl.exe`, а не на `study`: «always allow» выдавать
  нужно ему.

Файлы при этом читаются и по windows-пути напрямую, без `wsl.exe`: `stash/`, `NOTES.md`
и `config.env` доступны как обычные файлы рабочей папки.

Что и как попадает в ответ, настраивается двумя файлами рядом, без правки самой задачи:
`daily-digest-prompt.md` — шаги проверки, `daily-digest-template.md` — структура ответа.
Пути в промпте относительные, от рабочей папки задачи.

## Остальные команды

```
study state [--days N] [--local] [--no-save]   сводка Moodle и состояние работ
study digest [--days N] [--no-save]            только сводка Moodle
study answer <код предмета> <NN> [--tag T]     заготовка ответа по лабораторной

study me                                 владелец токена и число доступных функций
study courses [--all]                    курсы готовыми строками для config.env
study functions [подстрока]              функции, доступные токену
study call <функция> [ключ=значение ...] произвольный вызов
study assigns [--course id|код]          задания и сроки
study calendar [--days N]                события календаря (только дедлайны)
study grades [--course id|код]           баллы и БРС
study status <id-задания>                состояние ответа на задание
study files <курс> [--pull] [--all]      файлы курса: что появилось, забрать в stash/
study upload <файл>... [--itemid N]      загрузка вложений, печатает itemid
study submit <id> --text <файл> [--files <itemid>] --confirm    отправка ответа

study gv releases | release <тег> --title T --notes F | asset <id-релиза> <файл> | api <путь>
study sc releases | release <тег> --title T --notes F | asset <тег> <файл> | api <путь>
```

`--json` перед командой или после неё печатает те же данные машиночитаемо — ровно то,
что видит человекочитаемый вывод, без второго обхода API.

`study submit` без `--confirm` печатает план отправки и завершается с кодом 1: у заданий
`submissiondrafts=0`, сохранение ответа сразу считается сдачей и необратимо.

`gv` и `sc` определяют репозиторий по git-remote того каталога, откуда запущены
(`origin` для GitVerse, `src` для SourceCraft), и работают для любого курса; remote
учитывается, только если его адрес ведёт на соответствующий хостинг. `gv release`
подставляет SHA коммита по тегу: GitVerse не принимает имя ветки.

Повтор ключа в `study call` кодируется как массив Moodle:
`study call core_course_get_courses options[ids][0]=101`.

## Настройка

Всё изменяемое — в `config.env`.

| Задача | Что править |
|--------|-------------|
| другой набор курсов в новом семестре | строки `COURSE` |
| адрес Moodle, пути к токенам, глубина окна дедлайнов | `TUIS_URL`, `*_TOKEN_FILE`, `DIGEST_DAYS` |
| другой вид сводки | `daily-digest-template.md` |
| другие шаги проверки | `daily-digest-prompt.md` |
| новые источники данных | `studylib/moodle.py` + `studylib/digest.py` + запись в `tuis-api.md` |
| новый хостинг кода | класс в `studylib/hosting.py` + запись в `hosting-api.md` |

Строка курса: `COURSE <id> <код каталога или -> <название>`. Курс без каталога
(`-`) попадает в сводку, но локального состояния у него нет.

Без строк `COURSE` курсы определяются по календарю, но менее надёжно: курс, у которого
все задания скрыты ограничением доступа, в календарь не попадает. Если срок появится
у курса вне списка, сводка сообщит об этом отдельным разделом.

## Ответ на лабораторную и ссылки на записи

Ответ собирается командой `study answer <код предмета> <NN>`. Всё, кроме ссылок на
записи, определяется автоматически: адреса репозиториев — из git-remote, тег —
последний в репозитории или переданный через `--tag`, PDF отчёта и презентации — из
`_output/`.

Ссылок на скринкасты в API нет, поэтому они хранятся в `<код предмета>/tuis/labNN.env` —
десять полей: четыре записи (выполнение, отчёт, презентация, защита) на двух площадках
плюс два плейлиста.

```
RUTUBE_PLAYLIST=      VK_PLAYLIST=
RUTUBE_LAB=           VK_LAB=
RUTUBE_REPORT=        VK_REPORT=
RUTUBE_PRESENTATION=  VK_PRESENTATION=
RUTUBE_DEFENSE=       VK_DEFENSE=
```

Первый запуск `study answer` создаёт файл пустым и завершается. После заполнения ссылок
команда запускается повторно: незаполненное поле попадает в текст как
`ССЫЛКА НЕ ЗАПОЛНЕНА`, список недостающих печатается в конце. Готовый текст
сохраняется в `<код предмета>/tuis/labNN.md`, рядом перечисляются PDF для вложения.

Оба файла лежат вне репозитория курса, в `<код предмета>/tuis/`: в репозитории остаются
только исходники работы.

Отправка: `study upload <pdf>…` печатает `itemid`, затем
`study submit <id-задания> --text <код предмета>/tuis/labNN.md --files <itemid> --confirm`.

Полный порядок работы от выполнения до ответа на задание — `lab-submission.md`.

## Материалы курсов в `stash/`

Методички, слайды и программы хранятся в `<код предмета>/stash/`. Сводка туда ничего
не пишет, а только называет появившиеся файлы; загрузка — отдельной командой:

```bash
digest/study files <код предмета>          # что появилось с прошлого запуска сводки
digest/study files <код предмета> --all    # весь список файлов курса
digest/study files <код предмета> --pull   # скачать новые в stash/
```

Загружаются документы (`.pdf`, `.doc(x)`, `.md`, `.tex`, архивы и подобные) размером до
50 МБ. Пропускаются страницы курса (`mod_page` отдаёт `index.html` с нулевым размером),
видео, образы и всё, что крупнее предела. Файл считается имеющимся, если он лежит где
угодно внутри `stash/`, включая подкаталоги, — повторная загрузка не выполняется.

Новым считается изменённое после `last_run` из снимка состояния, то есть после прошлой
сводки. `--all` показывает всё и подходит для первичного наполнения.
