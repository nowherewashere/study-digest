# Порядок сдачи лабораторной работы

Чек-лист курсов, где к релизу репозитория прикладываются отчёт и презентация,
а в ответе на задание — ссылки на репозитории, релизы и скринкасты.

**Главное правило: релиз делается последним.** Тег и релиз выпускаются только тогда,
когда отчёт и презентация уже собраны, иначе к релизу нечего прикреплять.

1. **Выполнение работы** под запись скринкаста. Ветка `feature/labNN` через git-flow,
   коммит `feat(labNN): …`, `git flow feature finish`.
2. **Скриншоты.** Нарезать из записи (`ffmpeg`), сложить в `labs/labNN/report/image/`,
   вебку в углу закрасить.
3. **Отчёт** — `labs/labNN/report/<код>-labNN-report.qmd`, сборка `quarto render` →
   `_output/*.docx` и `*.pdf`. Разделы: цель, задание, теоретическое введение,
   выполнение с рисунками, отличия от методички, ответы на контрольные вопросы,
   выводы, список литературы, приложение с изменёнными файлами.
4. **Презентация** — `labs/labNN/presentation/<код>-labNN-presentation.qmd`, сборка →
   `*.pdf` (beamer) и `*.html` (revealjs).
5. **Коммит исходников**: `docs(labNN): add report and presentation`.
6. **Архив исходников**: zip с `.qmd`, `image/`, `bib/`.
7. **Релиз**: поднять `version` в `package.json` (иначе `standard-changelog` не добавит
   новый раздел), `git flow release start X.Y.Z` → `standard-changelog` →
   коммит `chore(site): release X.Y.Z` → `git flow release finish -s` →
   `git push origin/src master develop --tags` → копия `CHANGELOG.md` в `release/`.
8. **Файлы релиза** на обоих хостингах: отчёт `md`/`docx`/`pdf`, презентация
   `md`/`pdf`/`html`, архив исходников. Заливать `study gv asset <id-релиза> <файл>`
   и `study sc asset <тег> <файл>` из каталога репозитория. GitVerse отклоняет `.qmd`
   и `.html` — `.qmd` копировать как `.md`, `html` класть в zip; SourceCraft принимает всё.
9. **Скринкасты** на Rutube и VKvideo: четыре записи (выполнение, отчёт, презентация,
   защита) плюс плейлисты. Ссылки — в `<код предмета>/tuis/labNN.env`, десять полей;
   пустой файл создаёт первый запуск `study answer`.
10. **Ответ на задание**: `study answer <код предмета> NN` собирает текст со ссылками
    на плейлисты, видео, репозитории и релизы и кладёт его в
    `<код предмета>/tuis/labNN.md`. Отправка: `study upload <pdf>…` →
    `study submit <id-задания> --text <код предмета>/tuis/labNN.md --files <itemid> --confirm`.
    Без `--confirm` печатается план отправки; сдача необратима.

В репозитории курса остаются только исходники работы: ссылки на записи и заготовка
ответа лежат в `<код предмета>/tuis/` вне репозитория.

**Правка уже выпущенного релиза** (опечатка в отчёте, забытый файл): `git flow hotfix
start X.Y.Z+1` от `master` → исправление коммитом `fix(labNN): …` → bump `version` →
`standard-changelog` → `chore(site): release X.Y.Z+1` → `git flow hotfix finish -s` →
push обеих веток и тега → новый релиз с полным набором файлов на обоих хостингах.
Старый релиз не удалять.
